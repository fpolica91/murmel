# Team instructions

Coordinate through aweb shared state. Prefer small, reviewable tasks and clear
handoffs.

- Check `murmel workspace status`, `murmel mail inbox`, `murmel chat pending`, and `murmel work ready` before claiming work.
- Keep identity/team setup separate from filesystem and git worktree setup.
- Use `murmel team invite`, `murmel team join`, `murmel workspace connect`, and `murmel check` for team/workspace lifecycle.
- Use explicit `git worktree` commands for parallel local checkouts.
- Publish role and instruction changes deliberately; do not hide them in template setup.
- Never overwrite or delete `.murmel` state or private keys.
